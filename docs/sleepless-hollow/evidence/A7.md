## Implemented and deliberately gated

New non-Codable session snapshots and pure three-state evaluators. SSH fixtures
cover authenticated workers, pre-auth, listener-only, non-PTY, SFTP descendants,
unknown title formats and incomplete acquisition. Duplicate/invalid PIDs and
cycles on authenticated ancestry are rejected. Executable identity is a supplied
evidence field, not inferred from arbitrary command text. No live backend is
provided: SSHSessionReader returns unsupported by default. The classifier is
not a claim that process titles are a reliable production authentication API.

ConsoleSessionReader is a read-only utmpx prototype. It reads active console
accounting and filters setup/system accounts with reentrant lookup. Unresolved
accounts, malformed data, iteration failure or more than 4096 records yield
unavailable. It does not inspect VNC sockets or assume the current screen owner
represents all GUI sessions. O5 remains open for switching and virtual sessions.
Synchronous accounting/account lookup belongs on a worker in a future host.
Neither session reader is wired to Keepresso or policy enforcement.

Applied Claude's two A5/A6 follow-ups: documented exclusive observer consumption
for Core retention equivalence and recorded 32-bit interface counter improvement
K2. No throughput behavior changed. No new compatibility state introduced.

## Source research and U1

Primary sources inspected on 2 November 2026:

- [Apple QA1133](https://developer.apple.com/library/archive/qa/qa1133/_index.html)
  distinguishes current console ownership from all logged-in GUI sessions. It
  identifies utmpx for session enumeration and explains why current-owner APIs
  miss users switched to loginwindow. This archived guidance is not proof of
  present-day virtual-session behavior.
- Installed macOS 26.5 SDK `usr/include/utmpx.h`: active USER_PROCESS entries,
  tty/user fields and public iteration API. No private SessionInfo keys used.
- [Apple OpenSSH sshd-session.c](https://github.com/apple-oss-distributions/OpenSSH/blob/main/openssh/sshd-session.c),
  main: sets `[accepted]` for a new connection before authentication.
- [Apple OpenSSH monitor.c](https://github.com/apple-oss-distributions/OpenSSH/blob/main/openssh/monitor.c),
  mm_answer_pwnamallow: user-bearing `[priv]` title is set during account lookup,
  not proof of successful authentication.
- [Apple OpenSSH session.c](https://github.com/apple-oss-distributions/OpenSSH/blob/main/openssh/session.c),
  do_authenticated/session_proctitle: post-auth user and channel titles inform
  the synthetic fixtures; SFTP children can also carry user titles.

These OpenSSH main-branch sources are research references, not a pinned match
for this machine's binaries. Installed `sshd -V`: OpenSSH_10.2p1, LibreSSL 3.3.6.
No OpenSSH implementation was copied into the project.

U1: Keepresso's upstream preset matches `sshd:` or `sshd-session` anywhere in
command strings. Source shows pre-auth states containing those strings, which
corroborates the suspected overmatch. No live pre-auth experiment was performed,
no separate upstream fix was implemented, and the candidate remains suspected.
Keepresso's preset and existing behavior are unchanged.
